# ⑥ 체험·조작 포털 (`demo/`) — 휴대폰 카메라 체험

조작 화면 하나로 **Webots 시뮬레이션 조작**과 **이 기기(휴대폰·PC) 카메라 체험**을 함께 씁니다. 머리줄의 **'휴대폰 카메라' 스위치**(PC에서는 '이 기기 카메라')를 끄면 Webots 시뮬레이션(영상·조이스틱·제어)을, 켜면 그 기기의 카메라를 씁니다. `bash scripts/run.sh`가 관제 서버·연산 서버·Webots와 함께 켭니다 — 따로 켤 필요가 없습니다.

카메라를 켜면 누가 정면으로 다가오거나 벽으로 걸어갈 때 영상 위에 그 방향 칸이 빨갛게 뜨고, 영상 아래 '지금 동작' 줄과 회피 반사 흐름 패널·최근 기록이 시뮬레이션 때와 똑같이 바뀝니다. 정지할 때는 진동도 울립니다(지원하는 휴대폰만).

![휴대폰 카메라 체험 — 다가오는 무늬 앞에서 정지](../screenshots/demo_phone.png)
![PC에서 카메라 체험 — 같은 조작 화면](../screenshots/portal_camera.png)

```
브라우저 (PC·휴대폰 — 같은 조작 화면)                체험·조작 포털 (demo/server.py, 이 PC)
 스위치 끔: 웹소켓 ──────────────HTTP/HTTPS──▶       Webots 웹 서버(127.0.0.1:1234…)로 그대로 이어 준다
 스위치 켬: 카메라 → 줄인 밝기 영상(가로 240 px) ──▶  기기마다 휠체어 PC 파이프라인 하나 (루밍 → 커넥톰 → 공유 제어 그대로)
           자이로(돈 각도) · 내 움직임(서 있음/걷기)
           흐름 패널·지금 동작·겹쳐 보기·진동  ◀──── 흐름 상태 · 칸별 입력 · 작동 사건 (시뮬레이션 때와 같은 꼴)
```

관제 서버가 켜져 있으면 카메라를 쓰는 기기마다 관제 화면의 '휴대폰 체험' 카드로도 보입니다(위험도·칸별 입력·판단·회피 반사 작동 — 영상은 보내지 않습니다).

| 파일 | 하는 일 |
|---|---|
| `server.py` | 체험·조작 포털. 조작 화면(`simulation/webots/plugins/robot_windows/reflexguard/reflexguard.html`)을 주고, 화면의 웹소켓을 Webots로 이어 주고(`--webots-port`), `POST /api/frame`으로 카메라 영상 하나를 받아 흐름 상태·칸·작동 사건을 돌려준다. 기기마다 파이프라인을 따로 두고(최대 6대, 30초 쉬면 지움), 크기·속도 상한을 둔다. 포트 하나(기본 8443)로 이 PC와 휴대폰이 같은 주소를 쓴다 — `--https`면 HTTPS(자체 인증서를 `logs/demo_certs/`에 만든다)이고, 같은 포트로 온 `http://`는 `https://`로 넘긴다. `--dashboard host:port`면 카메라를 쓰는 기기마다 관제 서버에 'phone'으로 접속한다 |

## 실행

```bash
bash scripts/run.sh road           # 관제 서버 · 연산 서버 · 포털 · Webots를 한 번에 — 터미널에 조작 화면 주소가 나온다
```

**주소는 하나입니다: `https://<이 PC 주소>:8443`** — 이 PC와 휴대폰(같은 와이파이)이 같은 주소를 씁니다. 터미널에 나옵니다.

- 자체 인증서라 기기마다 처음 한 번 '안전하지 않음' 경고를 넘깁니다(이 PC에서는 `https://localhost:8443`도 같은 화면).
- 같은 포트로 `http://`를 치면 `https://`로 넘어갑니다.

- `--portal-local`이면 포털을 이 PC에서만 엽니다(휴대폰 접속 없음), `--no-portal`이면 켜지 않습니다(조작은 Webots 주소로).
- Webots 없이 카메라 체험만: `bash scripts/run_demo.sh` (따로 켠 Webots도 이으려면 `--webots-port 1234`). 이때는 처음부터 카메라가 켜진 채로 열립니다.
- 고른 모드(시뮬레이션 / 카메라)는 그 브라우저에 기억됩니다. 처음이면 시뮬레이션으로 열립니다(Webots가 없으면 카메라).

휴대폰에서:
1. 휴대폰을 PC와 **같은 와이파이**에 연결하고, 터미널에 나오는 `https://<주소>:8443`(PC와 같은 주소)을 엽니다.
2. 자체 인증서라 '안전하지 않음' 경고가 한 번 뜹니다. '고급 → 계속'으로 넘깁니다.
3. 머리줄의 **휴대폰 카메라** 스위치를 켜고 카메라·동작(아이폰) 권한을 허락합니다. 끄면 다시 시뮬레이션 조작(조이스틱)입니다.
4. 휴대폰을 세로로 가슴 높이에 들고 앞을 비춥니다. 서 있을 때는 누가 정면으로 다가오게 하고, 걸을 때는 '걷기'를 고른 뒤 벽 쪽으로 천천히 걸어 봅니다.

## 알아 둘 것

- **HTTPS가 필요한 이유**: 브라우저는 HTTPS(또는 같은 PC의 localhost)에서만 카메라를 열어 줍니다.
- **WSL에서 돌릴 때**: 터미널에 나오는 주소(172.x)는 WSL 내부 주소라 휴대폰에서 닿지 않습니다. 둘 중 하나가 필요합니다.
  - Windows의 `.wslconfig`에 `networkingMode=mirrored`를 넣고 WSL을 다시 켜기 (그러면 Windows의 와이파이 주소로 열립니다). 이 모드에서는 Windows 프로그램과 포트를 함께 쓰므로, 8080·8443 같은 포트를 Windows 쪽 프로그램이 쓰고 있으면 서버가 열리지 않습니다. WSL을 막 다시 켠 직후 1분쯤 관제 서버 포트가 막혔던 적도 있어, 관제 서버는 20초까지 다시 시도합니다.
  - 또는 Windows 관리자 PowerShell에서 포트 전달: `netsh interface portproxy add v4tov4 listenport=8443 connectaddress=<WSL 주소> connectport=8443`, 그리고 Windows 방화벽에서 8443 허용. 휴대폰에서는 Windows의 와이파이 주소로 엽니다.
  - mirrored 모드여도 Windows의 WSL 방화벽(Hyper-V 방화벽)이 바깥에서 WSL로 들어오는 접속을 막을 수 있습니다. 이 PC에서 확인해 보니 WSL 안에서는 `https://<와이파이 주소>:8443`이 열리지만, Windows 브라우저에서 같은 주소는 시간 초과였습니다(`https://localhost:8443`은 됩니다). 휴대폰에서 닿게 하려면 관리자 PowerShell에서 8443을 열어 줍니다(시도해 보지는 않았습니다):
    `New-NetFirewallHyperVRule -Name ReflexGuardPortal -DisplayName "ReflexGuard portal" -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol TCP -LocalPorts 8443`
  - Ubuntu에 직접 설치한 PC(실제 대상)에서는 그대로 됩니다.
- **휴대폰은 바퀴가 없습니다**: 속도를 모르므로 '서 있음'이면 정면 위주로만 보고(다가오는 것), '천천히 걷기·걷기'를 고르면 그 속도로 바닥이 퍼지는 몫과 몸이 지나갈 통로를 가립니다. 회전은 휴대폰 자이로로 보정합니다(세로로 들기 기준 — 방향이 반대로 잡히면 '회전 방향 반대').
- **카메라 값**: 휴대폰 카메라는 화각이 약 60~80°(기본 70°, 화면에서 바꿈), 숙임 0°, 높이 1.2 m로 봅니다. 휠체어 몸 가리개는 쓰지 않습니다. 보정 값(이득 등)은 시뮬레이션 카메라로 맞춘 그대로라, 휴대폰마다 반응 세기가 조금 다를 수 있습니다.
- **손떨림**: 가만히 들고 있어도 위험이 뜨던 원인은 손떨림(화면 전체가 1~2도 밀림)이었습니다. 루밍을 재기 전에 밀린 만큼을 재어 되돌리므로 줄었지만, 휴대폰을 비틀거나(기울기) 앞뒤로 흔들면 아직 뜰 수 있습니다. 두 손으로 가슴에 붙여 들면 가장 안정적입니다([흔들림 보정](../docs/connectome.md#흔들림-보정-손에-든-카메라)).
- **열린 고리**: 휴대폰은 판단대로 멈추지 않으므로(사람이 들고 있으니) 정지를 붙잡지 않고, 커넥톰이 위험하다고 하지 않으면 바로 풉니다. 정지 알림에는 '멈추세요 — 위험이 사라지면 풀립니다'가 뜹니다.
- **개인정보·보안**: 영상은 서버 메모리에서 계산만 하고 **저장하지 않습니다**. 관제 서버에는 칸별 입력·판단·휴대폰의 내부망 주소만 가고, 관제 서버가 그것을 기록 파일에 남깁니다. 인증이 없으니 같은 와이파이(내부망)에서만 쓰고 인터넷에 열지 않습니다. 휴대폰 수(6대)·영상 크기(320×320 이하)·속도(초당 30장)에 상한이 있습니다.
- **시뮬레이션도 이 주소로**: 포털이 Webots 웹 서버로 웹소켓을 그대로 이어 주므로, 휴대폰도 HTTPS 주소 하나로 시뮬레이션을 조작합니다. 인증이 없으니 같은 와이파이의 누구나 조작할 수 있습니다.
- **확인한 것과 못 한 것**:
  - Webots 녹화를 휴대폰처럼 보내 벽 앞에서 정지, HTTPS, 상한, 웹소켓 이어 주기(Webots가 꺼져 있으면 503)는 `tests/test_demo.py`로 확인합니다.
  - 가상 화면의 실제 Webots와 포털을 띄워, 포털을 거쳐 영상·흐름 상태·칸·작동 사건이 오고 키가 Webots에 닿는 것을 확인했습니다.
  - 브라우저(헤드리스 Edge, 가짜 카메라)로 스위치를 켜고 끄며 시뮬레이션 ↔ 카메라가 오가는 것, 다가오는 무늬 앞에서 정지하는 것을 확인했습니다.
  - **실제 휴대폰으로는 아직 해 보지 않았습니다**.
